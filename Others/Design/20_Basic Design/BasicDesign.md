# 基本設計の概要
要件定義書に記載された仕様を満たすために、どういった機能や画面が必要かを明確にしてドキュメント化する工程。
エンドユーザーや非エンジニアから見ても分かる粒度で設計を行っていく。

## 画面設計
### 画面一覧・画面遷移図
アプリ全体の構成・遷移を可視化する
- 画面ID・画面名
- 遷移元・遷移先
- アクセス権限

### 画面仕様書
各画面のUI/動作仕様を記載する
- 画面レイアウト
- 画面ID・画面名
- 入出力項目一覧
    - 項目名
    - 型（文字列／数値／日付など）
    - 入力制御（必須、桁数、フォーマット）
    - 初期値／デフォルト値
- ボタン・操作部品の仕様
    - 押下時の動作、遷移先など
- バリデーション
    - クライアント側、サーバ側
- メッセージ仕様（エラー、警告、完了）
- 表示データの取得元（API、DBなど）

## 機能設計
### 機能一覧
アプリ全体の機能をまとめる
会員登録機能、メール送信機能、決済機能など
- 機能ID・機能名
- 機能概要
- 担当モジュール（フロント、API、バッチなど）

### 機能仕様書
機能の振る舞いを明確化する
- 機能の目的
- 事前条件（ログイン済など）
- 事後条件（更新されるデータなど）
- 主なフロー（通常ケース）
- 例外フロー
- データの入出力
- 使用するAPI
- 使用する外部サービス

## API設計
### API一覧
- API ID
- エンドポイント
- HTTPメソッド（GET/POST/PUT/DELETE）
- 用途／概要

### API仕様書
- エンドポイント
- リクエスト
    - パラメータ名
    - 型
    - 必須/任意
    - 値の制約
- レスポンス
    - JSON 構造
    - フィールド定義
- ステータスコード
- エラーハンドリング仕様
- 想定最大データ量（ページング必要か、など）

## データベース設計
### データモデル図 / ER図
- テーブル名
- 主キー・外部キー
- 1対多、多対多の関係
- ER図（Entity Relationship Diagram）

### テーブル定義書
- テーブル名
- 目的
- 主キー
- 主要カラム
- リレーション（関連テーブル）

## 非機能要件設計
### 非機能要件定義書
- パフォーマンス要件
    - 応答速度（例：200ms以内）
    - 同時接続数
- セキュリティ要件
    - 認証方式（JWT/ OAuth2 / Cookieなど）
    - 送信データの暗号化
    - ログイン試行回数制限
- 可用性（SLA）
- バックアップ／リカバリ要件
- ログ要件（誰が・いつ・何をしたか）
- アクセス権限モデル
- 運用設計（ログローテート、監視項目）

## 外部インターフェイス設計
### 外部システム連携仕様書
- 利用する外部サービス
- 通信方式（REST / gRPC / Webhook）
- 認証方式
- 送受信データ仕様
- 障害時リトライ仕様
- バッチ連携の場合のタイミング

## バッチ設計
### バッチ一覧
- バッチID・バッチ名
- 処理概要
- 実行タイミング
- 入出力データ

### バッチ処理仕様書
- 流れ（フロー図）
- 入出力データ
- 例外処理
- 実行パフォーマンス要件
